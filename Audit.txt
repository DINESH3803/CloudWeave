C. Actual missing requirements
§7 / §10, demo 5 does not prove failure handling.

Evidence (demo.py:189-275):
It stops whichever worker holds chunk 0's first copy, not worker2. Earlier live runs stopped worker3. The README says worker2, so the documentation does not match the script.
It waits only 2 s during the outage. The heartbeat timeout is 15 s, so every worker still shows active, and neither detection nor repair is ever shown.
The final check counts copies with status stored, and the restarted worker re-marks its own copies as stored. The check passes even if repair never happened.
Impact: this is the demo the PDF describes most explicitly. As written it shows a download during an outage and little else.
Minimum fix (script only):
Stop worker2, and make sure the test object has a copy there.
Poll until worker2 is unhealthy (about 20 s) and print the number of usable copies per chunk, counting only copies on workers that are stored and active.
Download and verify the object.
Poll until every chunk has 2 usable copies again and print where they are.
Run docker start worker2, wait for active, and print the final state.
§8 / §10, demo 6 cannot show that corruption was detected.

Evidence (demo.py:281-327):
Step 4 prints copy statuses but asserts nothing. After a successful repair both copies show stored, which is exactly what you would see if the corrupt copy had never been read.
Whether the corrupt copy is read at all depends on the database's row order, because chunk_service.py:160-163 sorts only by worker health. Earlier live runs read it first 10/10 times, but nothing guarantees that.
Impact: the demo exits 0 without proving detection or repair.
Minimum fix:
Run sha256sum on the chunk file inside the target worker before the download (it should not match the stored checksum) and after (it should match), and assert both.
Make the read order deterministic by also sorting on worker_id in read_chunk, and have the demo corrupt the copy that sorts first.
§5.7, plain-text 500 responses.

Evidence: there is no catch-all exception handler in core/exceptions.py. A negative limit or offset reaches PostgreSQL and fails there (confirmed live). Names longer than 512 characters fail the same way.
Impact: low to medium. A grader who probes error handling sees a non-JSON error.
Minimum fix:
Add a catch-all Exception handler that returns a JSON 500.
Use Query(ge=0) for offset and Query(ge=1, le=1000) for limit.
Change the 404 message to "Object {id} not found".
§3 / §5.2, content type is always application/octet-stream through the bundled client and demo.

Evidence: client.py:23. Live: every stored object is octet-stream, including notes.txt.
Minimum fix: one line in the client using mimetypes.guess_type(path.name)[0] or "application/octet-stream".
§5.2, names outside Latin-1 cannot be downloaded (this is your call, since you rolled CW-08 back on purpose).

Evidence: objects.py:56. The live logs show the 500s.
Impact: only if a grader uploads such a name. résumé.pdf works because é is in Latin-1; Chinese characters, emoji and en dashes do not.
Minimum fix: about two lines that build the header with urllib.parse.quote: an ASCII filename= fallback plus filename*=UTF-8''…. That is far smaller than the 88-line module that was rolled back. The client already reads the fallback filename="…".
Deployment drift (operational, not a code change).

The live controller is the 09:08 image plus hand-copied files, including CW-08.
Fix: run docker compose --env-file .env -f deploy/docker-compose.yml up -d --build. Do not use -v, so the data is kept. After that, the live stack matches the source.
The following are not required by the PDF, and I would not fix them: trimming extra copies, cleaning up orphan files (worker2 has 16 files on disk but 15 tracked copies), a periodic integrity scan, using 409, and authentication.

One optional one-line hardening for §8: when a worker rejoins, registry.py:21-25 marks every chunk it reports as stored without comparing the checksum the worker sends. Comparing report.checksum with chunk.checksum and marking mismatches corrupt would stop a corrupt copy from rejoining as healthy.
